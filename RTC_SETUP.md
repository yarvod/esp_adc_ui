# Часы DS1302 для ESP32

На фото — модуль с выводами `RST`, `DAT`, `CLK`, `GND`, `VCC`, соответствующий DS1302.
Прошивка ESP-IDF использует это подключение. Дополнительная библиотека
часов не требуется: драйвер находится в `esp_adc/main/ds1302.h`.

## Подключение

Отключите питание ESP32 перед подключением проводов. Ориентируйтесь на подписи на платах,
а не на порядковый номер контакта в разъёме.

| Вывод модуля часов | Контакт ESP32 на фото |
| --- | --- |
| VCC | 3V3 |
| GND | GND, любой контакт земли |
| CLK | 25, то есть GPIO25 |
| DAT | 26, то есть GPIO26 |
| RST | 27, то есть GPIO27 |

`RST` модуля подключается именно к GPIO27. Это сигнал выбора часов (CE), а не сброс ESP32;
не подключайте его к `EN`. Пины 25, 26, 27 свободны в текущей прошивке.
АЦП остаётся на SDA=21/SCL=22, SD-карта — на CS=5/MOSI=23/MISO=19/SCLK=18.

Питайте модуль от **3,3 В** для совместимости с уровнями GPIO ESP32. При таком прямом
подключении не используйте 5 В/VIN. DS1302 поддерживает питание 2,0–5,5 В и трёхпроводный
интерфейс; описание сигналов и питания: [даташит производителя](https://www.analog.com/media/en/technical-documentation/data-sheets/DS1302.pdf).

Батарейка CR2032 сохраняет ход часов при отключении ESP32. В прошивке зарядка батарейки
DS1302 явно отключена, поскольку CR2032 не перезаряжается.

## Первый запуск

1. Подключите модуль и загрузите обновлённую прошивку ESP-IDF из проекта `esp_adc`.
   Дополнительная библиотека RTC не нужна.
2. Запустите обновлённое приложение (`main.py`) и укажите подключение к ESP32.
3. На вкладке `Настройки → Дата и время` нажмите **«Время компьютера»**, чтобы установить текущие дату
   и время. Либо выберите дату/время вручную и нажмите **«Установить»**.
4. Нажмите **«Прочитать часы»** для проверки. Строка показывает последнее прочитанное
   значение. Ввод и отображение используют часовой пояс компьютера; на компьютере в Москве
   это MSK (UTC+3).
5. Запустите запись или мониторинг. В мониторинге отображается время измерения с RTC.

Перед настройкой часов остановите запись на SD. Мониторинг и чтение часов используют
независимые HTTP-запросы и могут выполняться одновременно с разных устройств.
При переводе времени назад или большом скачке график начинает новый отсчёт; длительность мониторинга измеряется
монотонным таймером компьютера, поэтому перевод RTC не продлевает измерение.

Часы хранят время в **UTC**; приложение переводит местное время в UTC при установке и обратно
при показе. После первой настройки не нужно устанавливать часы при каждом перезапуске:
прошивка читает сохранённое время и не заменяет его временем сборки или компьютера.
Если модуль раньше использовался с местным временем, один раз нажмите «Время компьютера».

## Формат записей

Строки на SD сохраняют четыре столбца:

```text
datetime_utc; ADC0_mV; ADC1_mV; ADC2_mV
2026-10-12 15:30:45.123; 100.0; 200.0; 300.0
```

Первый столбец содержит **дату и время UTC в формате `YYYY-MM-DD HH:mm:ss.SSS`**:
год, месяц, день, часы, минуты, секунды и три цифры миллисекунд. Разделитель столбцов — `;`;
пробел между датой и временем не разделяет столбцы. Заголовок в примере пояснительный,
в файле записываются только строки измерений. HTTP API по-прежнему возвращает `timestamp_ms`.
Старые файлы остаются в прежнем формате. Имена новых файлов
`data_YYYYMMDD_HHMMSS_mmm.txt` также формируются прошивкой по UTC-времени RTC.

DS1302 хранит время с разрешением **одна секунда**. Для последовательных измерений между
секундами прошивка добавляет миллисекунды по монотонному таймеру ESP32, наблюдая смену
секунды RTC по умолчанию каждые 20 мс (настраивается от 20 до 200 мс через `/api/v1/config`
или `Настройки → Сбор и запись`). Это не означает абсолютную точность часов в 1 мс:
на неё влияют кварц DS1302, задержки установки и опроса. После загрузки фазу внутри секунды
прошивка уточняет на ближайшем переходе секунды.

При усреднении нескольких измерений метка относится к последнему измерению окна.
Параметры опроса АЦП, усреднения и сброса буфера на SD сохраняются в NVS отдельно от времени RTC;
подробности — в [HTTP_API.md](HTTP_API.md#настройки-измерений-и-сохранение).

Запись не начинается, если RTC недоступны, остановлены или содержат некорректную дату.
При потере часов во время записи прошивка останавливает запись и сохраняет накопленные
корректные точки. Мониторинг сообщает об ошибке вместо подстановки времени компьютера.
Проверка неподвижных часов занимает до примерно 1,5 с.

## HTTP API

Старый TCP-протокол заменён на HTTP API v1. Например:

```http
GET /api/v1/rtc
```

Ответ содержит `timestamp_ms` и `utc`. Установка московского времени 18:30:45:

```http
PUT /api/v1/rtc
Content-Type: application/json

{"utc":"2026-10-12T15:30:45"}
```

`GET /api/v1/adc` возвращает метку и три значения одной точки. Дата RTC должна быть
в диапазоне 2000–2099. Все остальные методы и примеры — в [HTTP_API.md](HTTP_API.md).
