# ESP ADC

Приложение для мониторинга ESP ADC по HTTP, записи текстовых файлов на SD-карту
устройства и управления термостатом Marlin. Измерения АЦП не сохраняются
автоматически на компьютере; файлы SD можно скачать вручную. Экспорт термостата
в CSV, статистику и PNG сохранён.

## Запуск из исходников

Python 3.11:

```sh
rtk uv venv
rtk uv pip install -r requirements.txt
rtk uv run python main.py
```

CLI использует стандартную библиотеку Python:

```sh
rtk uv run python cli.py --host 192.168.4.1 monitor
rtk uv run python cli.py --host 192.168.4.1 start --filename measurement.txt
rtk uv run python cli.py --host 192.168.4.1 status
rtk uv run python cli.py --host 192.168.4.1 stop
```

Для приложения требуется прошивка ESP с HTTP API v1: [HTTP_API.md](HTTP_API.md).

## Windows-релизы

GitHub Actions запускается на push, pull request, вручную и при отправке тегов
`v*`. В Windows Server 2022 устанавливаются **отдельные Python 3.11 x86 и x64**,
выполняются тесты, собираются дистрибутивы и проверяется запуск каждого EXE.
Python или Qt на компьютере пользователя устанавливать не нужно.

Каждая версия получает четыре файла:

- `EspAdc_Windows_x86_v1.0.0.zip` и его `.zip.sha256`;
- `EspAdc_Windows_x64_v1.0.0.zip` и его `.zip.sha256`.

Стабильные теги: `v1.0.0`, `v1.0.1`, `v1.1.0`.
Предварительные: `v1.1.0-alpha.1`, `v1.1.0-beta.1`, `v1.1.0-rc.1`.
Тег задаёт версию внутри EXE, манифеста и имён файлов. Старый тег `10` не запускает
новый релизный workflow.

Релиз публикуется только после успешных сборок обеих разрядностей и проверки
SHA-256. Сначала создаётся черновик, затем загружаются все файлы, и только после
этого релиз становится доступен. Опубликованная версия не перезаписывается.
Запуск workflow вручную создаёт артефакты для проверки без публикации релиза.

## Выпуск следующей версии

Сначала проверьте и закоммитьте изменения: release-скрипт требует чистое рабочее
дерево, чтобы в релиз не попала случайная незавершённая работа.

Windows:

```bat
release.bat v1.0.1 --dry-run
release.bat v1.0.1
```

macOS/Linux (сборка всё равно выполняется только на Windows в GitHub):

```sh
rtk bash release.sh -t v1.0.1 --dry-run
rtk bash release.sh -t v1.0.1
```

Скрипт проверяет формат и порядок версии, обновляет `application/version.py`,
создаёт коммит версии и аннотированный тег, отправляет текущую ветку и **только
этот тег** в origin одним атомарным push. При неудаче push локальный коммит и тег
сохраняются для повторной отправки.

Проверка CI и публикации:

```sh
rtk gh run list --workflow release.yml --limit 5
rtk gh run watch RUN_ID --exit-status
rtk gh release view v1.0.1
```

Локальная сборка на Windows:

```bat
python -m pip install --only-binary=:all: -r requirements.txt
build-win.bat --version v1.0.1 --arch x64
```

Для `--arch x86` нужен именно 32-битный Python. Скрипт проверяет разрядность
интерпретатора и PE-заголовки обоих EXE. Основное приложение собирается как
`onedir`, отдельный updater — как `onefile`, и оба включаются в один ZIP.

## Установка и обновление

Распакуйте **всю папку `EspAdc`** из ZIP в доступный для записи каталог, например
`C:\Users\имя\Apps\EspAdc`, и запустите `EspAdc.exe`. Разрядность выбранного ZIP
должна подходить системе; 32-битная программа на 64-битной Windows продолжает
получать обновления x86.

В меню **Программа → Версии и обновление…** выберите опубликованную версию:
доступны новые, предыдущие и предварительные версии, а также описание релиза.
Текущая версия помечена. Для версий без ZIP и SHA-256 нужной разрядности доступно
открытие страницы релиза для ручной загрузки.

После подтверждения архив загружается в фоне. До закрытия программы проверяются
SHA-256, структура ZIP, манифест, выбранная версия и разрядность EXE. Загрузку
можно отменить. После её завершения программа останавливает мониторинг и
термостат, сохраняет настройки и ждёт завершения рабочих потоков.

Updater запускается из временной папки, ждёт завершения основного процесса,
подготавливает новую папку установки, сохраняя `settings.ini` и пользовательские
файлы, заменяет папки и запускает программу снова. При ошибке копирования,
замены или запуска восстанавливается предыдущая установка.
Журнал ошибок: `%TEMP%\EspAdc-updater.log`.

Проверку стабильных обновлений при запуске можно выключить в меню «Программа».
Она показывает уведомление в строке состояния, установка начинается только
после выбора пользователя. Из исходников доступен просмотр релизов; автоматическая
замена файлов работает только в собранном Windows-приложении.

Первый дистрибутив с новым updater нужно распаковать вручную. Старые приложения
без механизма обновления не смогут установить его сами.

## Проверки

```sh
rtk uv run python -m unittest discover -s tests -p 'test_*.py'
```

Тесты обновления работают с локальными ZIP и fake-ответами GitHub, проверяют
выбор разрядности, отмену, повреждённую загрузку, неверную версию, небезопасные
пути, сохранение настроек и откат. Тесты HTTP API используют локальный сервер.
